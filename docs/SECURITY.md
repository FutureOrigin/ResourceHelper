# 安全策略

## 支持的版本

| 版本 | 是否接收安全修复 |
| --- | --- |
| 1.1.x（当前） | ✅ |
| 更早版本 | ❌（请升级） |

## 报告安全问题

**请不要开公开 issue。**

请通过 GitHub 的私密漏洞报告提交：仓库页 → **Security** → **Report a vulnerability**。

报告里请尽量包含：

- 受影响的版本（`out/ResourceHelper/manifest.json` 的 `version`）与浏览器版本；
- 复现步骤或最小样例页面；
- 影响判断（能读到什么、能写什么、需要用户做什么操作）；
- 如果可能，给出修复建议。

我们会尽量在 **7 天内**给出首次回应，并在修复发布后致谢（除非你希望匿名）。
在修复发布前，请不要公开细节。

## 在范围内的东西

- 扩展权限的越权使用（例如不该发起的网络请求、不该读取的数据）；
- 内容脚本的注入面（XSS、DOM clobbering、页面可控字符串进入扩展上下文）；
- 消息通道的信任边界（页面 / 内容脚本 / 后台 / offscreen 之间的消息伪造）；
- 绕过"必须用户显式操作"的限制（例如未经点击就发起带 Cookie 的整页快照抓取）；
- 供应链问题（构建脚本、依赖——目前零运行时依赖）。

## 明确不在范围内

- **DRM 绕过**：本扩展不提供也不接受任何 DRM 绕过能力，相关报告按功能请求处理；
- 需要物理接触设备、或需要用户安装恶意扩展才能成立的问题；
- 第三方站点的漏洞（请报告给对应站点）；
- "能下载受版权保护的内容"本身——这是产品功能，不是安全问题；
- 仅影响已停止支持版本的问题。

## 我们不会做的事

- 不收集、不上传任何用户数据（没有服务器，也没有遥测）；
- 不在仓库里存放密钥、令牌或个人数据；
- 不通过"安全更新"静默改变数据处理方式。隐私相关的变更会写进 [CHANGELOG.md](CHANGELOG.md) 与 [PRIVACY.md](PRIVACY.md)。
